## 1. 概述

**目标**：在 ContextMenu 内部维护不变量「**外框尺寸 = MenuPanel 内容尺寸**」（items 非空时）。items 增删/separator/字体/主题/缩放引起 `MenuPanel::recalculateSize()` 后，自动同步 ContextMenu 外框宽高；**只改 width/height，保持 x/y**；不触发 `show()`/可见性/焦点/watcher/锚定/钳制。

**根因**：`MenuPanel::recalculateSize()` 只更新自身 rect（`Menu.cpp:502-560`）；`ContextMenu` 外框只有单向传播（`ContextMenu::setRect` 外框→面板，`ContextMenu.cpp:77-83`），反向（面板→外框）缺失——`addItem`/`addSeparator` 后外框保持旧值（设计器实测 140×80 vs 内容 170×85）。

## 3. 设计

### 3.1 不变量

1. **非空 items**：`ContextMenu` 外框 `width/height == MenuPanel` 内容尺寸（`m_menuPanel->getRect().width/height`）
2. **空 items**：外框保持当前 rect（不出现 0 尺寸——CR 要求）
3. **x/y 永不因同步改变**；同步不触碰 visible/focus/watcher/锚定模式/位置钳制
4. 手动 `setRect` 语义：x/y 生效并保留；**非空 items 时 w/h 以内容尺寸为准**（内容覆盖初始值，与设计器"放置 140×80 → 填 items 后变 170×85"一致）

### 3.2 同步机制：MenuPanel 尺寸变化通知（决策点 1；B2 已闭合）

- `MenuPanel` 增加变化通知：`using SizeChangedHandler = std::function<void(const SRect&)>;` + `setOnSizeChanged(handler)`（可选注册，MenuBar 等既有使用方不注册 → 零影响）
- `MenuPanel::recalculateSize()` 末尾：**仅非空 items 且尺寸变化时**调用 `m_onSizeChanged(newRect)`（空 items 分支直接 return，**不通知**——外框不会被置 0）
- **生命周期（B2-1 v3 修正：懒注册）**：**构造函数中不注册**（构造期间 `make_shared` 尚未完成，`getThis()`/`weak_from_this()` 为空/无效）。改为 **`ensureSizeCallback()` 懒注册**：
  ```
  if (m_sizeCallbackRegistered || !m_menuPanel) return;
  auto self = dynamic_pointer_cast<ContextMenu>(getThis());   // make_shared 完成后有效
  if (!self) return;                                          // 构造期间静默跳过
  m_menuPanel->setOnSizeChanged([weak = weak_ptr<ContextMenu>(self)](const SRect& r) {
      if (auto cm = weak.lock()) cm->applySyncedSize(r.width, r.height);
  });
  m_sizeCallbackRegistered = true;
  ```
  调用点：`addItem`（两个重载）/`addSeparator`/`show`/`syncSize`/`create`/`setRect` 入口——覆盖"直接 `make_shared` 后立即 `addItem`、不经过 `create`"的路径（`CreateContextMenu`/Builder 同样经这些入口）。首次操作时 shared 所有者已建立 → 注册成功。
  `~ContextMenu()` 额外 `m_menuPanel->setOnSizeChanged(nullptr)` 显式解绑（双保险）。
- **执行时机（B2-2）**：回调只在 `recalculateSize()` **尺寸最终稳定后**触发一次（函数末尾）；析构/空 items/尺寸未变均不触发
- **受控更新（B2-3）**：helper `void applySyncedSize(float w, float h)`：
  ```
  if (w <= 0 || h <= 0) return;
  if (m_rect.width == w && m_rect.height == h) return;      // 幂等
  ControlImpl::resized(SRect(m_rect.left, m_rect.top, w, h)); // 受控：只更新宽高（ControlBase.cpp:339-342）
  ```
  **不调用** `Panel::setRect`/虚 `resized` 的布局链——ContextMenu 非布局容器、无百分比子控件（`Panel::resized` 的 reflow/resolveChildPercentages 对 MenuPanel 无意义且可能重入）；MenuPanel 已在 `recalculateSize` 内自管 `layoutItems`。后续若 ContextMenu 引入 layout/anchor/percent 子项，须重新评估此语义（写入设计约束）。

### 3.3 公开 API（C++；N1/N2 已闭合）

- **`bool syncSize()`**：显式同步。语义 = **先 `m_menuPanel->recalculateSize()`（按当前字体/内容强制重算），再 applySyncedSize(panel.w, panel.h)**；返回 `true`=已按内容同步，`false`=无面板/空 items（外框保持，不同步）——与 C ABI 1/0 一致
- **`SRect getMenuPanelRect() const`**：返回 **MenuPanel 局部坐标**（相对 ContextMenu 内容区，正常 `(0,0,w,h)`；**空菜单返回 `(0,0,0,0)`**，已在 C ABI/Binding 文档注明）
- `addItem`/`addSeparator` 后由面板回调自动同步（无需显式调用）；`syncSize()` 用于字体时序兜底/测试/宿主主动校验
- **生命周期测试要求**：ContextMenu 析构后 MenuPanel 被外部持有 → 回调 weak 失效，无悬垂/崩溃

### 3.4 状态矩阵（B4 已闭合，逐项纳入测试）

| # | 场景 | 操作 | 外框 w/h | x/y | 回调/syncSize |
|---|---|---|---|---|---|
| S1 | 初始空 items | 构造（10×10）/手动 `setRect` | 保持设置值 | 接受设置值 | 不触发（空分支不通知） |
| S2 | 空 → 首次添加 | `addItem` | = 内容尺寸 | 保持 | 触发 → 同步 |
| S3 | 非空 | add/remove/separator/字体/行高/缩放 | = 内容尺寸 | 保持 | 触发 → 同步 |
| S4 | 非空 → 删除全部 | `removeItem`（至空） | **保持最后一次非空尺寸**（不置 0、不回初始） | 保持 | 空分支不通知 → 外框不动 |
| S5 | 再添加（空→有） | `addItem` | = **新**内容尺寸 | 保持 | 触发 → 同步 |
| S6 | 空菜单手动 `setRect` | `setRect(x,y,w,h)` | **接受 w/h** | 接受 | 无 |
| S7 | 空菜单 `syncSize()` | `syncSize()` | 不同步（保持） | 保持 | 返回 `false` |
| S8 | 非空手动 `setRect` | `setRect(x,y,w,h)` | w/h 被内容覆盖（panel 重算后同步） | 接受 x/y | 内部重算触发（幂等） |
| S9 | 非空 `syncSize()` | `syncSize()` | = 重算后内容尺寸 | 保持 | 返回 `true` |

### 3.5 设计态 / 运行态 / 缩放 / 主题

- **设计态**（未 `show`、create 后宿主控制 visible）：`addItem` → 面板重算 → 回调同步 ✓；不触碰 watcher/焦点/可见性
- **运行态**：`show()` 流程不变（其 `setRect` 已设外框，回调幂等）；`close()` 后 items 变化同样同步
- **缩放/DPI**：`MenuPanel::refreshScaleWith` 已重算（`Menu.cpp:386-404`）→ 回调同步 ✓
- **主题**：颜色不改变尺寸；字体/字号经 `setFontSize`/`setItemHeightRatio` 重算 ✓
- **顺带修复**：`MenuPanel::setFontName` 末尾补 `recalculateSize()`（字体名影响字宽；已创建时重算，未创建时不强制）——见决策点 5

### 3.6 LayoutParser 联动（B1/B3 已闭合）

- **rect 持久化（B1）**：`parseContextMenu` 新增 `rect` 解析——`if (j.contains(kJsonRect)) cm->setRect(parseRect(j[kJsonRect]))`（x/y 生效；非空 items 时 w/h 随后被内容覆盖，空 items 时保留）——保存/打开后 x/y 不丢失
- **schema 同步（B1）**：`docs/schema/declarative-ui.schema.json` 的 `context-menu` 定义补 `"rect": {"$ref": "#/$defs/rect"}`（选填；`--strict` 校验通过）
- **items 解析自动同步**：`cm->addItem()` → `MenuPanel::recalculateSize()` → 回调 → 外框跟随（无需额外代码）
- **显式兜底（B3 修正）**：`cm->create()` **之后**调用 `cm->syncSize()`——create/setContext 后字体真实可用，`syncSize` 内部强制 `recalculateSize` 再同步，解决首遍兜底估算；**不再**在 create 前调用
- 旧布局未声明 items：无重算 → 外框保持 JSON rect（或默认 10×10）；有 rect 无 items 时 rect 完整保留 ✓

## 5. 决策点

### 决策点 1：同步机制
**建议**：MenuPanel 尺寸变化回调（可选注册，MenuBar 等零影响）——覆盖 addItem/separator/removeItem/字体/行高/缩放**全部**重算路径；ContextMenu 侧幂等静默更新。
- 备选：ContextMenu 逐个覆写 addItem/addSeparator/setRect（漏 `setFontSize` 等内部路径）；每帧轮询（浪费、有滞后）。

### 决策点 2：空 items 语义
**建议**：不同步、保持当前 rect（CR 要求，避免 0 尺寸；`recalculateSize` 空分支的 0×0 不落到外框）。
- 备选：同步为 0×0——设计器选择框消失，不可用。

### 决策点 3：API 形态
**建议**：自动同步为主 + `syncSize()` 显式兜底 + `getMenuPanelRect()` 只读（CR 建议名称全给），C ABI/Binding 同步。
- 备选：仅自动同步（设计器无法主动测量/校验）；仅显式 API（忘记调用即滞后）。

### 决策点 4：手动 `setRect` 的 w/h 语义
**建议**：非空 items 时 w/h 以内容尺寸为准（手动 w/h 仅作空菜单初始值/兜底）；x/y 永远保留。
- 备选：手动 w/h 覆盖内容（面板被外框裁切/不匹配，与不变量冲突）。

### 决策点 5：顺带修 `MenuPanel::setFontName` 不重算
**建议**：`setFontName` 末尾补 `recalculateSize()`（已创建时）——否则字体名变化后宽高不同步（CR 验收"字体变化后尺寸正确"）。
- 备选：不改（记录为已知限制，验收不通过风险）。

### 决策点 6：LayoutParser 联动（B3 修正）
**建议**：items 解析链自动同步 + **`create()` 之后**显式 `syncSize()`（内部强制 `recalculateSize` 后同步；字体真实就绪）——create 前调用已废弃（无法解决首遍兜底估算）。
- 备选：纯自动（首遍兜底差异残留风险）。

### 决策点 7：ContextMenu 位置持久化（B1 新增）
**建议**：`context-menu` 新增**选填 `rect`**（parseContextMenu 解析 + schema 补字段）——x/y 持久化（保存/打开/导出一致）；w/h 非空 items 时以内容为准、空 items 时保留。旧布局无 rect → 保持默认/SetRect 值。
- 备选：位置不持久化（删除验收承诺）——违背设计器需求与 CR 验收，废弃。

### 决策点 8：syncSize 语义（B3/N2 新增）
**建议**：`bool syncSize()` = 强制 `recalculateSize()` + 同步；返回 false 表示空菜单未同步（C ABI 1/0 对齐）。`getMenuPanelRect()` 返回局部坐标、空菜单 0×0。
- 备选：`void` 无返回值（无法区分空菜单/成功），废弃。

## 9. 风险与边界

- **不触碰**：`show()`/`open()`/`close()`/watcher/焦点/可见性/锚定/视口钳制（同步仅经受控 `applySyncedSize` 更新宽高）
- **MenuBar 零影响**：回调可选注册，MenuBar 的 MenuPanel 不注册（N4 回归断言，测试 12）
- **空菜单**：外框保持 rect（无 0 尺寸；`recalculateSize` 空分支不触发回调，§3.4 S1/S4/S6/S7）
- **字体时序（B3）**：`create()` 后置 `syncSize()`（内部强制重算）；运行时 `show()` 两遍重算后回调再次同步
- **移除全部 items**：面板 0×0 不落到外框（保持最后一次非空尺寸）——§3.4 S4
- **受控更新语义（B2）**：`ControlImpl::resized` 只更新宽高；如未来 ContextMenu 引入 layout/anchor/percent 子项，须重新评估（设计约束）
- **生命周期（B2）**：weak 回调 + 析构解绑；MenuPanel 外部持有不悬垂
- **兼容性（N3）**：旧布局/旧调用零回归；旧 DLL 缺新符号 → Binding 返回 false（不静默），设计器禁用入口

## 12. 实施注意（v3 复核非阻塞项，实施时逐项落实）

1. **懒注册时序**：`ensureSizeCallback()` 调用点均为公开入口（addItem/addSeparator/show/syncSize/create/setRect）；**构造链（ContextMenu 构造 → MenuPanel 构造）不得触发**——构造期 `getThis()` 为空时 ensure 直接 return（静默跳过），且 C++ 构造期间虚调 `setRect` 分派到基类版本（不经过 ContextMenu override），双重保证
2. **syncSize 幂等**：内部 `recalculateSize()` 已触发回调 `applySyncedSize`（幂等），随后显式再调一次 `applySyncedSize` 必须无副作用（幂等断言覆盖）
3. **parseRect 路径诊断**：`parseContextMenu` 解析 rect 时用 `pushJsonPath(kJsonRect)` 包裹（与既有控件一致），保留 LayoutParser 的 JSON 路径错误诊断（`parseRect` 内 logWarn 含字段缺失/类型）
4. **旧 DLL 缺符号**：Binding RESOLVE 失败 → `ContextMenuSyncSize`/`ContextMenuGetMenuPanelRect` 返回 false；**设计器侧禁用相关入口并提示**（设计器配合项 §3.8 补充，不静默）
5. **测试路径真实性**：全部用例使用真实 `make_shared<ContextMenu>`（或 C ABI `CreateContextMenu`/Builder）路径，不得绕过 shared 所有者机制构造对象（覆盖懒注册场景）
