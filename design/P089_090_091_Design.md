## 1. P0-91 确认（含设计器附注"池往返崩溃"根因）

### 1.1 页签几何/悬停不可得（确认）
- 页签宽 = `measureText(title)+2*padding`（TabControl.cpp:206 区）；`TabPage.tabRect`（include/TabControl.h:21）与 `m_hoveredTab`（:93，MouseMove→`hitTestTab` :318）均已算好但**无任何导出**（getIntProperty 仅 currentIndex/fontSize）→ 设计器只能以 currentIndex 变化启发式判定"点中项/空白"，固有误差 ✓。

### 1.2 页序调整 + 池往返崩溃（**根因已复现并定位**）
- 复现（Temp/temp_p091b_probe）：3 页 → `TabRemovePage(0)`（池保活）→ `TabAddPage` → `TabSetPage(2, pooledA)`（**合法索引**）→ **段错误 rc=139**；
- **根因（UAF 顺序缺陷）**：`UICornerstone_TabSetPage` 包装层（src/UICornerstoneAPI.cpp:1747+）先 `detachPoolTake(instance, page);`（**丢弃返回值**）——池内页失去唯一强引用 → **shared_ptr 归零、对象立即析构**；随后才 `dynamic_cast<ControlImpl*>(pg)->shared_from_this()` → **在已释放对象上调用** → 段错误 ✗（对照 `AddChildControl`：先 `shared_from_this()` 再 take，无此问题）；
- **次生缺陷**：`TabSetPage` 未做**上界**检查——越界索引时同样先消费池 → `setTabPage` no-op → 页被销毁且不在任何池（句柄悬垂；探针首版即此路径 rc=139）；
- 结论：设计器"TabRemovePage 池保活 + AddPage/SetPage 重挂"模拟**不可用**的根因即上述两点（P0-69② 保活路径与 SetPage 包装层交互缺陷）。

### 1.3 方案
| # | 内容 |
|---|---|
| ① `UICornerstone_TabGetItemRect(inst, tab, index, float* x,y,w,h)` | 直接导出 `relayout` 的 `TabPage.tabRect`（越界返回 0）；Binding `TabGetItemRect(Control&, int, SRect&)` |
| ② `hovered-tab` 只读读回 | `TabControl::getIntProperty("hovered-tab")` → `m_hoveredTab`（与 MenuBar `hovered-index` P0-82 同款；新增常量 `kHoveredTab`）——点击帧读 ≥0=点中该项 / -1=空白，实现最轻 |
| ③ `UICornerstone_TabMovePage(inst, tab, from, to)` | 引擎新增 `TabControl::moveTab(from, to)`：**完整迁移 `TabPage` 结构**（title/page/leadingControl/tabRect 重排）＝ `erase + insert`（不走 remove+add，不涉池）；页 shared_ptr 原样迁移；越界返回 0；Binding `TabMovePage(Control&, int, int)`；`m_currentIndex` 随迁移正确重映射 |
| ④ **修复 SetPage 包装层（必做）** | a) **先取强引用**（`shared_from_this()`）**再** `detachPoolTake`；b) **上界检查**（`index < getTabCount()`）置于任何池/父级变更之前，越界返回 0；c) 防御：`setTabPage` 失败路径将页**放回保活池**（不悬垂）；④ 与 ③ 独立——即使设计器改用 `TabMovePage`，该路径亦须安全（设计器附注要求） |

## 2. P0-90 确认：页签配色可配置

**核实**：`kSelTabColor/kHoverTabColor/kNormTabColor`（TabControl.cpp:16-18，绘制 :253-255）、`kIndicatorColor`（:19，:261）、`kContentBgColor`（:22，:303）**均硬编码常量**，无属性通道 ✓（现有仅 `page-background`/`selected-text`/text 四态）。

**方案**（单色 + 读回，命名对齐 P0-72④ item 颜色家族）：
- `tab-background`（常态页签底，默认 37,37,42）/ `tab-hover-background`（60,60,70）/ `tab-selected-background`（45,45,52）——`setColorProperty/getColorProperty` 直达，draw 改用成员；
- 可选（Q-2）：`tab-indicator-color`（选中指示条，默认 0,122,204）、`tab-content-background`（内容区底色，50,50,56）——建议一并给（同一批，成本一行/键）；
- 文档：tabcontrol.html 属性表 + appendix/properties.html；CABI/Binding 通用 SetColor/GetColor 直通（零新增接口）。

## 3. P0-89 确认：未注册 handler 诊断日志

**核实**：`parseEvents` 系列对 `m_handlers.find(name)` 未命中**静默跳过**（LayoutParser.cpp 共 20 处 find；:3058 等）→ 宿主"先 LoadLayout 后 RegisterAction"时点击无反馈、难定位 ✓。

**方案**：新增 `LayoutParser::lookupHandler(name, controlId)`（未命中 `logWarn("handler not registered: %s (control: %s)")` 并返回空）→ 替换 20 处 find 调用（机械）；日志级别 warn（与现有 logWarn 一致）；设计器侧无需随批。
