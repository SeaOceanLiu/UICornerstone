5.7 拖拽框架（Drag & Drop）

拖拽框架把「按下 / 阈值 / 移动 / 命中目标 / 释放 / 预览与落点提示」统一到引擎：引擎本就持有事件队列与全部几何， 宿主只需处理语义与数据（收 drag-over/drop 事件、读载荷、同步自己的模型）。 覆盖范围：单实例内（含子视口）；跨实例拖放（如工具箱→画布）由宿主自管，可经 drag-active 查询拖拽状态。

5.7.1 快速开始

JSON 声明（通用键，任意控件可加）：

{ "type": "tree-view", "id": "src", "draggable": true, "reorderable": true,
  "rect": { "x": 20, "y": 20, "w": 240, "h": 320 }, "items": [ ... ] }

{ "type": "panel", "id": "dst", "droppable": true,
  "rect": { "x": 300, "y": 20, "w": 300, "h": 320 } }

C ABI / C++ Binding 注册与处理：

UICornerstone_SetBool(inst, tree, "draggable", 1);
UICornerstone_SetBool(inst, panel, "droppable", 1);
UICornerstone_SetCallback(inst, panel, "drag-over", onDragOver, NULL);
UICornerstone_SetCallback(inst, panel, "drop",      onDrop,     NULL);
UICornerstone_SetCallback(inst, tree,  "drag-start", onDragStart, NULL);
UICornerstone_SetCallback(inst, tree,  "drag-end",   onDragEnd,   NULL);

5.7.2 属性

属性 / JSON 键类型默认说明
draggableBoolfalse可拖拽源；引擎自动填充载荷（tree 节点 / list 行 / tab 页；其它控件为控件自身）
droppableBoolfalse可放置目标（收 drag-over/drop）
reorderableBoolfalse同控件内置换序（tree 换序·换父 / list 行换序 / tab 页换序），见 5.7.5
drag-thresholdFloat4拖动阈值（px）；未超阈值按下+释放保持普通点击语义
drag-visualBooltrue默认视觉开关（跟随光标的 ghost + 落点指示线）
drag-data / drag-userdataString / Ptr—宿主自定义载荷（设置后 kind=HOST；userData 透传不校验生命周期）
drag-acceptBooltrue仅 drag-over 回调内设置：0=拒绝（不触发 drop，drag-end.dropped=0）
drag-activeBool（只读）—本控件是否当前拖拽源（跨实例/自绘轮询）
drag-ghost-background / drag-ghost-text / drag-indicator-colorColor—默认视觉主题色（取自源控件）

5.7.3 事件

事件名侧载荷说明
drag-start源payload超过阈值开始拖动（载荷在按下时已捕获，拖动期间不变）
drag-over目标payload + hint目标或落点变化时触发（实时高亮/接受判定）；目标/落点变化自动重置接受态
drop目标payload + hint释放且被接受（drag-accept != 0）
drag-end源payload + hint + dropped结束（含 Esc/失焦中止与拒绝）；dropped=1 表示已投放
reorderedtree / listpayload + hint内置换序完成（5.7.5）
tab-reorderedtab-controlpayload + hintTab 页换序完成：payload.index=from，hint.index=to

5.7.4 载荷与落点（语义化）

载荷 UIDragPayload（ev->data.drag.payload）：kind（UI_DRAG_KIND_*）/ id / index / text / userData / source。自动填充：

kind来源自动填充
UI_DRAG_KIND_TREE_NODETreeView节点 id / 行索引 / label / 节点 userData
UI_DRAG_KIND_LIST_ROWListView行 id / 行索引 / 首列文本 / 行 userData
UI_DRAG_KIND_TAB_PAGETabControl页标题 / 页索引
UI_DRAG_KIND_CONTROL其它控件源控件句柄（source）
UI_DRAG_KIND_HOST任意（drag-data/userdata）宿主字符串/指针

落点 UIDropHint（ev->data.drag.hint）——宿主收到的是语义而非像素：

hint.kind目标控件index / targetId
UI_DROP_HINT_BEFORE / AFTER / INTOTreeView行索引；目标节点 id（before/after=同级插入，into=置入）
UI_DROP_HINT_ROWListView行索引 + 行 id
UI_DROP_HINT_INDEXTabControl插入位索引
UI_DROP_HINT_INSIDE通用控件—

5.7.5 内置换序（reorderable，opt-in）

同控件拖拽换序零配置：源/目标均为该控件且 reorderable=true 时，引擎在 drop 后直接执行数据迁移并发语义事件 （reordered / tab-reordered），宿主据此同步模型：

{ "type": "tab-control", "draggable": true, "droppable": true, "reorderable": true, ... }
UICornerstone_SetCallback(inst, tab, "tab-reordered", onTabReordered, NULL);
// onTabReordered：from = ev->data.drag.payload.index; to = ev->data.drag.hint.index;

换序也可程序化调用（公开 API，不依赖拖拽）：

UICornerstone_TreeViewMoveNode(inst, tree, "nodeId", "newParentId", -1);  // 换序/换父（-1=追加）
UICornerstone_ListViewMoveRow(inst, lv, from, to);                        // 行换序（to=最终索引）
UICornerstone_TabMovePage(inst, tab, from, to);                           // 页换序（currentIndex 重映射）

5.7.6 行为细节与边界

  • 点击语义保留：未超阈值即释放 = 普通点击（不触发 drag-start）；
  • 中止：拖动中按 Esc 或窗口失焦 → drag-end（dropped=0）；
  • 子视口：拖动期事件由 owner 统一接管，目标解析跨子视口（坐标自动换算）；
  • 跨实例：不支持（工具箱→画布等由宿主自管；drag-active 只读查询可辅助状态管理）；
  • 默认视觉：ghost（载荷文本）+ 落点指示线；置 drag-visual=false 关闭后由宿主自绘；
  • 接受/拒绝：默认接受；drag-over 回调内 SetBool("drag-accept", 0) 拒绝（目标/落点变化自动重置为接受）。

5.7.7 完整示例：树 → 面板拖放

示例覆盖发起侧（源）与接收侧（目标）两侧：源树声明 draggable 并处理 drag-start/drag-end； 目标面板声明 droppable 并处理 drag-over（可拒绝）/drop。C ABI 写法如下（Binding 同名方法一一对应）：

// inst 为全局实例句柄（UIInstance，见 5.4 C ABI 程序化构建）
// ── 一、准备：找到源与目标（此处假设由布局 JSON 创建，见 5.7.1 的 JSON 声明）──
UIControlHandle tree  = UICornerstone_FindControl(inst, "src");
UIControlHandle panel = UICornerstone_FindControl(inst, "dst");

// ── 二、发起侧（源）：注册可拖拽 + 源侧事件 ──
UICornerstone_SetBool(inst, tree, "draggable", 1);
UICornerstone_SetCallback(inst, tree, "drag-start", onDragStart, NULL);
UICornerstone_SetCallback(inst, tree, "drag-end",   onDragEnd,   NULL);

static void onDragStart(UIControlHandle ctl, const UIEventData* ev, void* user) {
    const UIDragPayload& p = ev->data.drag.payload;    // 按下时已捕获，拖动期间不变
    // 例：把载荷摘要暂存到宿主状态（p.kind==UI_DRAG_KIND_TREE_NODE）
    printf("drag-start: kind=%d id='%s' index=%d text='%s'\n",
           p.kind, p.id, p.index, p.text);
}
static void onDragEnd(UIControlHandle ctl, const UIEventData* ev, void* user) {
    const UIDragPayload& p = ev->data.drag.payload;
    int dropped = ev->data.drag.dropped;               // 1=已投放；0=Esc/失焦中止或被拒绝
    printf("drag-end: id='%s' dropped=%d\n", p.id, dropped);
}

// ── 三、接收侧（目标）：注册可放置 + 目标侧事件 ──
UICornerstone_SetBool(inst, panel, "droppable", 1);
UICornerstone_SetCallback(inst, panel, "drag-over", onDragOver, NULL);
UICornerstone_SetCallback(inst, panel, "drop",      onDrop,     NULL);

static void onDragOver(UIControlHandle ctl, const UIEventData* ev, void* user) {
    const UIDragPayload& p = ev->data.drag.payload;
    const UIDropHint&    h = ev->data.drag.hint;
    // 过滤：只接受树节点载荷；其余拒绝（不触发 drop，drag-end.dropped=0）
    if (p.kind != UI_DRAG_KIND_TREE_NODE) {
        UICornerstone_SetBool(inst, ctl, "drag-accept", 0);
        return;
    }
    printf("drag-over: node='%s' hint.kind=%d\n", p.id, h.kind);   // 可据此实时高亮
}
static void onDrop(UIControlHandle ctl, const UIEventData* ev, void* user) {
    const UIDragPayload& p = ev->data.drag.payload;
    const UIDropHint&    h = ev->data.drag.hint;
    printf("drop: node '%s' (%s) -> hint.kind=%d index=%d targetId='%s'\n",
           p.id, p.text, h.kind, h.index, h.targetId);
    // TODO：把 p.id / p.userData 接到自己的数据模型（树控件数据由你维护）
}

// ── 四、拖动时序（无需宿主干预）──
// 树节点按下 →（超过阈值）drag-start → 光标跨控件/子视口 → drag-over（目标变化即触发，
// 可在其中接受/拒绝）→ 释放：被接受则 drop + drag-end(dropped=1)；Esc/失焦 → drag-end(dropped=0)；
// 未超阈值即释放 = 普通点击（不触发任何拖拽事件）。

若源与目标是同一个 tree/list/tab 控件，直接把两侧 reorderable 置 1， 引擎会执行数据迁移并发 reordered/tab-reordered（见 5.7.5），无需 drop 里手写换序逻辑。
