9 问题定位手段

9.1 自动化测试（首选）

仓库内置全量自动化测试，几乎每个控件与特性都有对应用例。遇到疑似 bug，先跑相关测试定位是「库的问题」还是「你的用法问题」：

build_scripts\build_test.bat test_button          :: 构建单个测试
build_scripts\build_test.bat all sdl3             :: 三后端全量
cd build\sdl3\test\Debug
test_button.exe auto=3                            :: 自动跑 3 秒，exit=0 通过
测试覆盖
test_<control>_cabi各控件行为 + 属性 + 事件
test_*_visual_cabi视觉状态断言（hover / 焦点环 / 内容传递）
test_animation / test_luotiani_cabiLuotiAni 动画
test_apiC ABI 全功能冒烟（7 控件 + JSON 布局 + 事件绑定）
test_event / test_focus事件分发 / 焦点系统
test_layout / test_layout_advanced布局引擎（百分比 / 嵌套 / 对齐）
test_multi_instance_cabi / test_multiviewport_cabi多实例 / 多视口（K1-K8）
test_property_cabi统一属性系统（Set/Get 对称 + 边界条件）

9.2 断言与日志

  • 测试程序打印 PASS/FAIL 并带函数名；exit=0 表示全过；
  • 核心库事件 / 控件关键路径有日志输出（带调试标签的实例可区分多实例）；
  • 创建实例时传 debugLabel（UIInstanceConfig），多实例问题可分辨日志来源。

9.3 调试 API（Release 可用）

API用途
UICornerstone_Debug_RouteMouseTarget(inst, x, y)鼠标目标解析探针（P0-52②）：返回 1=owner（浮层优先/空白区）/ 0=子视口——路由问题快速定位
UICornerstone_Debug_ValidateHandle(inst, ctl) / Binding DebugValidateHandle(ctl)句柄归属校验（P0-84c）：1=属于本实例，0=不属于/非法。跨实例句柄误用（Release 下曾静默容忍）会导致"控件属错实例 → 输入/焦点通路不达"类问题；建议在动态行/控件构建后自检并记录日志。核心库同时已全构建启用归属校验（不属于即日志+拒绝）

9.5 常见错误模式

现象原因处置
Binding Create 返回 nullptr核心 DLL 缺失 / 路径错误Config.WithCoreLibraryDir(...) 指定目录；确认 DLL 与后端匹配
控件不显示未 addControl / visible=false / 被遮挡确认挂到 BENCH 或父容器；查 z 序与 transparent
点击无反应控件未启用 / 未设置回调 / 被上层控件挡住SetBool("enabled", true)；SetCallback；检查命中控件
中文乱码文件编码或 raylib 码点限制源码/布局文件用 UTF-8 with BOM；raylib 需码点扩展
多实例窗口内容闪动 / 串扰raylib 单窗口架构查能力位 MULTI_WINDOW，headless 实例跳过渲染（见 5.2）
动画不播放 / 跳帧未 prepare / 帧号越界 / frameRate=0先 prepare()；确认 overview 必填键齐全
布局不生效rect 缺省 / handler 未注册 / 热加载未 pollrect 必填；RegisterAction 名字对齐；每帧 reloader.poll()
焦点环不显示m_focusRingAlwaysVisible=false 且非键盘聚焦Tab 键聚焦；或设 alwaysVisible

9.5 最小复现模板

把问题收敛到最小工程（一个 main + 一个控件），对照 test/ 中同控件用例的结构。若你的用法与测试一致仍出错，可到 GitHub 提交 issue，附：后端、版本、最小代码、auto= 测试输出。
