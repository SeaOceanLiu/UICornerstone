5.7 使用其它后端（SFML / raylib）

UICornerstone 的界面代码与后端无关：同一份业务代码，仅编译开关 / 实例创建参数不同即可切换后端。

5.7.1 三后端对比

SDL3（推荐）SFMLraylib
风格原生 C APIC++ 风格C 风格
功能最全较全基础
多窗口✓✓✗（单窗口）
部署需 3 个 DLL（SDL3/SDL3_ttf/SDL3_image）SFML DLL 组单 DLL，最简
中文✓✓需码点扩展
能力位四能力全有四能力全有无 MULTI_WINDOW
vsync 配置vsync + swap-ratiovsyncvsync（创建期全局）

5.7.2 编译时选择后端

:: Windows
build_scripts\build.bat sdl3        :: SDL3 后端
build_scripts\build.bat sfml        :: SFML 后端
build_scripts\build.bat raylib      :: Raylib 后端

:: Linux（通用 CMake）
cmake -B build -DUICORNERSTONE_BACKEND=SFML -DCMAKE_BUILD_TYPE=Debug
cmake -B build -DUICORNERSTONE_BACKEND=RAYLIB -DCMAKE_BUILD_TYPE=Debug

5.7.3 运行时选择后端

// C ABI：从插件名创建实例（同一 DLL 内含全部后端？否——按构建时后端）
UICornerstone_CreateInstanceFromPlugin("sfml", NULL);
UICornerstone_CreateInstanceFromPlugin("raylib", NULL);

// C++ Binding
UICornerstone::UICornerstone::Create(
    UICornerstone::UICornerstone::Config{}.WithBackend("raylib"));

// 样例命令行（backend= 与 auto= 任意顺序混用；auto= 无人值守冒烟）
sample_cpp_hosted.exe backend=sfml auto=4
「运行时选择」指插件加载路径的写法统一；实际可用的后端取决于编译时构建的 DLL/库。Binding 的 Config 通过 backendSearchPath / coreLibraryDir 指定动态库搜索位置，样例可内置多后端 DLL 按参数加载。

5.7.4 后端能力位与条件化

uint32_t caps = UICornerstone_GetBackendCapabilities(g_inst);
bool multiWindow = (caps & UICORN_BACKEND_CAP_MULTI_WINDOW) != 0;
if (multiWindow) { /* 正常创建第二窗口 */ }
else { /* headless 降级：Window::isHeadless()，跳过渲染 */ }

详见 5.2 多视口与多窗口 与 10 后端差异及后端配置。

5.7.5 后端配置键（运行时）

// C ABI：SetBackendConfig / SetBackendConfigInt / SetBackendConfigBool
// inst == NULL 时为创建期全局默认（raylib 的 vsync 必须这样设置）
UICornerstone_SetBackendConfig(NULL, "vsync", "1");
UICornerstone_SetBackendConfig(g_inst, "swap-ratio", "1");   // SDL3 专用

// 只读探测
char name[64];
UICornerstone_GetBackendConfig(g_inst, "renderer-name", name, sizeof(name));
