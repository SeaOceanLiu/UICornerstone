4.21 Splitter（分割条）

Splitter 是可拖拽的分割条：关联两侧 sibling 控件，拖拽时实时调整两侧尺寸，支持最小尺寸约束与分割比例。继承链：Splitter → ControlImpl → Control。

4.21.1 控件的创建

// C++
Splitter(Control* parent, const SRect& rect, float xScale = 1.0f, float yScale = 1.0f);
SplitterBuilder(parent, SRect(244, 60, 6, 200))
    .setOrientation(false)              // false=垂直分割（左右分栏）
    .setLinkedControls(firstPanel, secondPanel)
    .setSplitRatio(0.4f).build();

// C ABI
UIControlHandle sp = UICornerstone_CreateSplitter(g_inst, 244, 60, 6, 200, 1 /*orientation*/, 1.0f, 1.0f);

// JSON
{ "id": "mySplitter", "type": "splitter",
  "rect": { "x": 244, "y": 60, "w": 6, "h": 200 },
  "orientation": "vertical",
  "first-linked": "panelFirst", "second-linked": "panelSecond",
  "thickness": 6, "ratio": 0.4, "first-min": 50, "second-min": 50,
  "events": { "onSplitterMoved": "onSplitterMoved" } }
JSON 中 orientation: "vertical" → 垂直分割（左右分栏），其余为水平；rect 可省略，由 first/second 控件边界自动推导。Splitter 节点必须排在关联面板之后。

4.21.5 C++ Binding 样例

auto splitter = ui->CreateSplitter(244, 60, 6, 200, 1 /*orientation*/);
splitter.SetFloat(PropertyNames::kRatio, 0.4f);
splitter.SetFloat(PropertyNames::kThickness, 6.0f);
splitter.SetCallback(PropertyNames::kEventMoved, [](const Event& e) {
    printf("ratio = %.3f\n", e.GetMovedPosition());
});
// 关联控件经 "first-linked" / "second-linked" 属性或 AddChild 顺序管理

4.21.6 C ABI 调用样例

// orientation: 0=垂直分割, 1=水平分割；first/second 为被分割控件
UIControlHandle left  = UICornerstone_CreatePanel(g_inst, 20, 20, 200, 300, 1.0f, 1.0f);
UIControlHandle right = UICornerstone_CreatePanel(g_inst, 240, 20, 200, 300, 1.0f, 1.0f);
UIControlHandle sp = UICornerstone_CreateSplitter(g_inst, 20, 20, 420, 300, 0, 1.0f, 1.0f);

UICornerstone_SetPtr(g_inst, sp, "first-linked", left);
UICornerstone_SetPtr(g_inst, sp, "second-linked", right);
UICornerstone_SetFloat(g_inst, sp, "ratio", 0.4f);

static void onMoved(UIControlHandle ctl, const UIEventData* ev, void* ud) { }
UICornerstone_SetCallback(g_inst, sp, "moved", onMoved, NULL);

4.21.7 布局引擎模式（v1.1.1 增强）

Splitter 放在 布局引擎容器（panel + v-flow / h-flow）的 children 中即自动进入引擎模式：成为引擎的一等元素，不再需要 firstPanel/secondPanel 关联——两侧面板就是它的前后邻居，任意数量 Splitter 按链式累计布局（三分栏、四栏、嵌套弹性面板内再放两条水平 Splitter 均支持）。

{ "type": "panel", "id": "middle", "rect": {"x": 0, "y": 0, "w": 1000, "h": 300},
  "layout": { "type": "h-flow", "gap": 0 },
  "children": [
    { "type": "panel", "id": "left",   "rect": {"w": 240, "h": 300} },
    { "type": "splitter", "id": "spl", "orientation": "vertical", "thickness": 8 },
    { "type": "panel", "id": "canvas", "rect": {"w": 0, "h": 300}, "flow-weight": 1 },
    { "type": "splitter", "id": "spr", "orientation": "vertical", "thickness": 8 },
    { "type": "panel", "id": "right",  "rect": {"w": 240, "h": 300} }
  ] }

引擎模式规则：

  • 分段：Splitter 占自身 thickness 宽（高）且与邻居之间不计 gap；流内固定/弹性分配语义不变（flow-weight 生效）。
  • 两式拖拽：前段（左/上）固定 → 改前段固定宽；前段弹性且后段固定 → 改后段固定宽（前段自动弹性补偿）；双侧弹性 → 前段锁定为固定（基础保护）。每次拖拽触发引擎整链重排，多个/嵌套 Splitter 位置始终链式正确、互不覆盖。
  • 1:1 跟手：拖拽位移以拖拽起点为基准 + 累计增量换算（固定基准，避免逐帧叠加），坐标经画布/视口缩放全链换算——窗口缩放（DPI / fit / stretch）下依然 1:1。
  • 手柄模式：无关联面板（无 first-linked/second-linked）且无链接对象时，Splitter 仅作为"拖拽手柄"：拖动自身位置并经 onSplitterMoved 上报 ratio（0~1），布局由应用侧维护。
  • 引擎外自动模式：放在普通容器（无 layoutEngine）且设置 first-linked/second-linked → 原有自动联动（左右面板独占父容器）不变。

三种模式互斥优先级：引擎模式（布局引擎容器内）> linked 自动模式（引擎外 + 有面板）> 手柄模式（其余）。

历史修复：拖拽"超动/不跟手"根因为逐帧以"当前宽（已含上一帧增量）+ 累计增量"双重累加（实测 5.7× 超动）；已改为"拖拽起点宽 + 累计增量"固定基准。鼠标路过非分条区域光标残留箭头问题同批修复（默认光标改为独立创建的系统默认光标，不再取"当前光标"缓存）。
