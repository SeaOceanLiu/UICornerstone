# 《09 启动 Launcher 设计》引擎评审

> 评审方：UICornerstone 引擎
> 日期：2026-11-05
> 对象：`D:\GitSpace\CornerstoneDesigner\design\09_启动Launcher设计.md`（v0.1）
> 请求：`D:\GitSpace\CornerstoneDesigner\Temp\Launcher_Design_引擎评审请求.md`

## 结论

**有条件通过。** 独立进程、进程内单实例、进度管道与 Designer 启动参数方案均符合当前引擎边界；窗口隐藏/显示与 `GetNativeWindowHandle` 的跨后端契约需要补齐，否则只能作为 SDL3 宿主临时方案，不能作为跨后端/跨平台契约。

## Q1 独立进程 + UICornerstone 实例

通过。

- 引擎当前多实例模型是**同线程、同主循环**；Launcher/Designer 两个独立进程各自加载 DLL、backend、字体/资源，互不共享进程内全局状态。
- 两个进程可同时加载同一 `UICornerstone.dll` / `UIBackend_sdl3.dll` / assets；Windows 下 DLL 装载是进程级，无引擎侧额外禁止。
- 需保证 Launcher 和 Designer 不共享可写资源目录；只读加载同一 assets 即可。

## Q2 主窗口隐藏/显示

**当前结论：有条件可用。**

- SDL3 后端的 `UICornerstone_GetNativeWindowHandle()` 返回底层 `SDL_Window*`（当前实现 `Window::nativeHandle()` 直接返回）：`SDL_HideWindow/SDL_ShowWindow` 可直接使用，且不需要重建实例。
- 但这是 **backend-specific** 句柄：SFML/raylib 不是 `SDL_Window*`，Binding/引擎没有承诺 `GetNativeWindowHandle` 对任意后端都可作为 SDL_Window*。因此：
  - 只适用于明确使用 SDL3 的 Designer/Launcher；
  - 宿主必须动态解析 SDL3 符号（不要把 SDL3 头/链接强加到 Launcher 核心层），并在 backend 名称为 `sdl3` 时才转换句柄；
  - `GetNativeWindowHandle` 返回空（headless/无窗口实例）时必须降级。
- `Create` 后先可见再 `SDL_HideWindow` 可能有一帧窗口闪烁，且可能抢 Launcher 焦点；若接受该风险可作为临时方案。
- **建议引擎补充**（小 API，非本 Launcher CR 的阻塞条件但推荐）：
  - `UIWindowFlags::Hidden`（值对齐 `SDL_WINDOW_HIDDEN`）创建期隐藏；
  - `UICornerstone_SetWindowVisible(instance, int visible)` 运行期显示/隐藏（SDL3/SFML/raylib 各自实现，失败返回 0）。
  - 这样宿主不直接碰 SDL，Designer 隐藏/显示和 Launcher 跨后端都成立；建议另立 CR（如 `CR20261105003`）评审。
- 若不改引擎：Launcher 设计应把“原生句柄隐藏”标注为 **SDL3-only 临时实现**，并在非 SDL3 后端直接显示窗口或使用平台原生启动画面。

## Q3 代码创建 loading 控件

通过，前提：

1. 先 `UICornerstone_Create` 得到实例并 `SetViewport`；
2. 再使用 `CreatePanel/CreateLabel/CreateProgressBar` 等工厂（这些 API 会挂到 Bench 并 `create`）；
3. 配置 `resourceRoot`（至少 `fonts`/必要 assets），否则 Label 字体加载失败；不依赖 `LoadLayout`/项目主题；
4. 首帧前调用 `ProcessEvents/Update/Render/Present`；Launcher 自己的主题可用显式颜色，不需要 `ApplyTheme`；
5. 不要调用 `LoadLayout` 初始化 Launcher，避免把 Launcher 的控件写入设计器布局模型。

## Q4 进度管道

通过。

- 阶段进度由 Designer 在自身 `App::init` 阶段发送，不需要引擎启动回调；引擎日志/平台日志走 stdout，管道独立。
- 子进程异常/退出由 Launcher 监控进程句柄/PID；引擎无需额外清理接口。
- `auto=2/auto=3` 测试应直接启动 Designer，不经过 Launcher，避免把启动包装器纳入引擎测试口径。

## Q5 首帧与资源

- Launcher 自身创建 UICornerstone 实例预计 200–300ms 可接受；首帧目标 <1s 与 CR20261105001/CR20261105002 的 Designer 启动优化分开验收。
- 两个 SDL3 进程互不干扰；Launcher 与 Designer 各自拥有窗口/渲染器。
- 不为 Launcher 裁剪 assets 也能运行；若裁剪，至少保留 `fonts` 与 Launcher 实际引用的图片/主题资源，不要依赖 Designer 的 `loadSettings`/项目布局。
- 当前无“无窗口/延迟窗口”后端 API；窗口隐藏标志是最小的后续优化，不在本设计内承诺。

## Q6 跨平台

有条件通过。

- 进程创建、管道、窗口隐藏抽象到 `LauncherPlatform` 的方向正确；引擎本身不依赖 Windows-only Launcher 行为。
- 窗口隐藏部分：若使用 `GetNativeWindowHandle`，只能保证 SDL3；跨后端/跨平台需要 Q2 的引擎 API 或平台层各自实现。
- 字体/assets 路径、资源根目录和 UICornerstone 初始化顺序在两个平台都需遵循引擎现有资源约定。

## 需要引擎补充的 API/CR（建议）

1. `UIWindowFlags::Hidden`（创建期隐藏，避免首帧闪烁/抢焦点）。
2. `UICornerstone_SetWindowVisible(UIInstance, int)` / Binding `SetWindowVisible(bool)`（运行期显示/隐藏，跨后端）。
3. 可选的 backend 查询接口供宿主判断 `GetNativeWindowHandle` 类型（若暂不新增，宿主可通过 Config 已知 backend 名称判断）。

建议以独立 CR（`CR20261105003` 窗口可见性）评审；在未交付前，Launcher 可按 SDL3-only 临时方案实施，但需在设计文档标注限制。

## 其它风险

- `--startup-hidden` 若在 `Create` 后才隐藏，可能出现窗口闪烁/焦点切换；验收需加入“Launcher 前台、主窗口无闪烁”检查。
- Launcher 退出时机与 Designer 主窗口显示要原子化：先显示主窗口再发 ready/关闭 Launcher，避免两者都不可见。
- 两个进程同时读取同一 assets 目录无写冲突；若 Designer 热重载或写资源文件，需避免与 Launcher 读取竞争。
- 首帧指标需区分 Launcher 首帧、Designer 首帧和总启动；报告需同机 Release 多次中位数。

结论：Launcher 设计边界清晰，可按 SDL3-only 临时方案与 CR20261105003 并行实施；CR5003 完成后再切换跨后端窗口可见性。
