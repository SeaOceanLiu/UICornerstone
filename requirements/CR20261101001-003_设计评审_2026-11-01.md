## 0. 总体结论

三份设计的总体方向可行：复用内部 EditBox、统一生命周期出口、事件携带旧/新值、C ABI + Binding 双通道，与 CR 目标一致。

但**当前版本暂不通过**，不建议直接进入实施。需先解决 3 个阻塞项，并确认若干范围/生命周期问题；修订后由设计器再次评审。

## 1. 阻塞项

### B1. `UIEventData` ABI 扩展方式不安全，且三份设计不统一

**问题**：

- CR-001 §4.5/§8 在 `UIEventData` 末尾追加 `editOldText/editNewText/editReadOnly`，会改变结构体大小；`UIEventData` 没有 `structSize`/版本字段（见 `include/UICornerstoneAPI.h:886-899`）。
- **新 Binding + 旧 DLL**：旧 DLL 只分配旧结构，新 Binding 读取尾部字段属于越界访问，不能靠“同批重编”覆盖所有宿主。
- CR-001 §4.5 写的是 2 个指针 + `editReadOnly`，§8 又写“末尾追加 2 指针”，字段数量前后矛盾。
- CR-003 §4.3 写“新增 union 成员（或末尾追加；实现时统一为一处）”，方案未定；与 CR-001/002 的顶层字段方案也不一致。
- 现有 `fireCCallback` 对 `Grid` 只拷贝 `row/col/asc`（`src/ControlBase.cpp:1053-1064`）；若只扩内部 `GridPayload` 而不改公开 union，事件字段不会到达 Binding。

**建议（推荐）**：

不增加 `UIEventData` 顶层字段，扩展现有 union 成员；现有 `drag` 成员使 union 足够大，可避免结构体尺寸变化：

```c
struct {
    int row;
    int col;
    int asc;
    const char* oldText;   /* begin/cancel 有；edited 有 */
    const char* newText;   /* 仅 edited 有 */
    int editReadOnly;      /* begin/cancel 的只读会话标志；edited 恒 0 */
} grid;

struct {
    const char* id;
    void* userData;
    const char* oldText;
    const char* newText;
    int editReadOnly;
} treeNode;

struct {
    int col;
    float oldWidth;
    float newWidth;
    int canceled;
} resize;
```

- `fireCCallback` 同步把内部 `GridPayload/TreeNodePayload` 拷入对应 union 成员；
- 保留旧字段偏移；增加 `static_assert(sizeof(UIEventData) == 旧值)` 或等价测试，确认 union 尺寸未变；
- 旧 DLL 会 `memset` 整个事件结构，新 Binding 读扩展字段得到空值/0，安全；新 DLL + 旧宿主只读旧字段，也安全；
- CR-001/002/003 全部统一为这一方案，删除“末尾追加”和“union 或末尾二选一”的未决表述。

如果坚持使用 `UIEventData` 顶层字段，则必须先引入 ABI 版本/`structSize` 并在 Binding 侧判空/拒绝旧 DLL；不建议在本批引入两套机制。

### B2. ListView 覆盖层“随父裁剪”假设不成立

**问题**：

- `ListView::draw()` 在行内容绘制后执行 `popClipRect()`，再调用 `ControlImpl::draw()` 绘制子控件；`ControlImpl::draw()` 本身不按 ListView 内容区裁剪（`src/ListView.cpp` 子控件绘制段、`src/ControlBase.cpp:200-209`）。
- 因此内部 EditBox 作为 ListView 子控件，**可能盖住表头、滚动条或 ListView 外区域**；CR-001 §4.2 的“裁剪到内容区”没有对应实现机制。
- 部分可见行尤其危险：EditBox rect 超出内容区时不会自动被父裁剪。

**建议**：

- 明确二选一：
  1. 给 EditBox 增加显式的列表内容区裁剪（或复用 ListView 内部裁剪路径）；或
  2. 部分可见时不显示覆盖层，只允许完全可见的单元格进入编辑（实现更简单，需写入验收）。
- TreeView 也要按实际子控件绘制路径验证；不能假设与 ListView 相同。
- 增加截图/区域测试：编辑首行、末行、部分可见行、横向滚动、滚动条附近，确认不越过表头/滚动条/控件边界。

### B3. CR-003 的“引擎拥有手势”与 session/运行时互斥未闭合

**问题**：

- CR-003 §4.4 明确写“引擎不监听鼠标（设计态手势由宿主驱动）”；引擎拥有的是命中/宽度计算，实际鼠标仍由设计器转发。这与“引擎拥有手势”的产品表述存在语义差，需先确认接受哪种定义：
  - A. 引擎拥有命中/宽度/session，设计器只转发指针（当前设计）；
  - B. 引擎真正接管设计态鼠标事件（需要额外的设计态交互模式/事件路由，当前设计未覆盖）。
- 设计未定义新 API session 与运行时 `m_dragCol` 的互斥：
  - API session 进行中，运行时 `handleEvent` 仍可因鼠标按下进入 `m_dragCol`；
  - 运行时拖拽进行中，`BeginColumnResize` 仍可能成功；
  - 两条路径都可能修改 `setColumnWidth`，导致 oldWidth/事件错乱。
- 未定义 session 在控件隐藏/禁用/销毁、列增删、`setColumns`、外部 `setColumnWidth`、滚动/缩放时的清理策略。

**建议**：

- 在 CR-003 中明确归属：若接受 A，改写“引擎拥有手势”为“引擎拥有命中、宽度计算与 session；设计器拥有鼠标转发”，并让用户确认。
- 增加单一 session 约束：`m_dragCol >= 0` 时 Begin 返回 0；API session 活跃时运行时列头拖拽拒绝或先取消；外部 `setColumnWidth`/列结构变化/隐藏/禁用/销毁取消 session；事件发送顺序写入文档。
- `column-resize-changed` 仅在宽度实际变化时发送，避免同坐标重复事件。
- 增加并发/生命周期测试（见 §4）。

## 2. 按 CR 的具体问题

### CR20261101001（ListView 单元格编辑）

- **§4.1 属性数量笔误**：表格有 4 个属性（`cell-editing`、`editable-columns`、`read-only-columns`、`read-only-row-ids`），但下文写“parseListView 增两键解析”“schema 增两键”。应为四键，或明确哪两键是本次新增；schema/`additionalProperties:false` 同步。
- **只读语义（Q3，已确认）**：用户确认（2026-11-01）保留“只读行/列仍进入编辑、EditBox 只读、Enter/失焦按 cancel”，并新增 `read-only-columns`/`read-only-row-ids`；设计按此实施，不再作为范围待确认项。
- **焦点**：Enter/Esc 销毁 EditBox 后，`FocusManager::unregisterControl` 会清空当前焦点；设计未说明把焦点还给 ListView 还是原焦点控件。否则编辑结束后键盘导航中断。点击其他控件导致的失焦提交除外（焦点已转移）。
- **Tab**：Q6 说“Tab 提交且不切换单元格”，但未说明 EditBox 子类如何拦截全局 Tab 焦点遍历；需明确拦截并消费 Tab，或改为“Tab 提交并切换”。
- **双击/拖拽顺序**：需明确只在单元格文本区双击进入；表头分隔线、滚动条、前置控件、拖拽阈值优先；第二击不应重新触发行拖动。
- **销毁事件**：控件销毁时发 `cell-edit-cancel` 可能把已失效句柄交给宿主。建议销毁路径只清理、不回调；隐藏/禁用路径才发 cancel。
- **字符串生命周期**：`oldText/newText` 仅回调期有效可以接受，但必须存到稳定成员或调用期局部变量；不要让指针指向 `getCell()` 返回的临时值。
- **API 失败语义**：`BeginEditCell` 在 `cell-editing=0`、隐藏/禁用、越界、列不可编辑、行不存在时返回 0；建议把“隐藏/禁用/未 create”也写入失败矩阵。
- **只读属性**：`edit-old-text`/`edit-new-text` 是否保留请定稿；若保留，需与事件载荷一致（begin/cancel 的 new 为空），并在回调结束后清空。

### CR20261101002（TreeView 节点编辑）

- **共享 ABI 问题**同 B1；不要在 CR-002 单独采用顶层字段。
- **`GetEditingId` 缺只读出参**：ListView 有 `GetEditingCell(... outReadOnly)`，TreeView 只有 `GetEditingId(out,cap)`；建议补 `outReadOnly` 或明确只读状态只能从 `begin` 事件读取，保持两个控件 API 口径一致。
- **`GetEditingId` 缓冲语义**：设计写“`snprintf` 语义/out=NULL 查长度”，请与现有 C ABI 的 `GetString`/P107 风格统一（`outLen` 或明确的截断语义），避免 Binding 端再次分叉。
- **覆盖层裁剪**：同 B2；TreeView 的缩进/箭头/前置图标/部分可见行需实际验证，不能假定子控件被内容区裁剪。
- **只读语义/`read-only-ids`（已确认）**：同 CR-001，用户确认保留，按本批范围实施。
- **Tab/焦点/销毁事件**：与 CR-001 同一套规则，需在共享机制中统一实现，不要只写在 ListView 侧。
- **展开/折叠**：设计已规定立即取消；建议补充“取消时是否发 `node-edit-cancel`、readOnly 标志”的明确语义。

### CR20261101003（ListView 列宽拖拽）

- **B3 的归属/session 互斥**是首要问题。
- **事件载荷**：统一使用 `UIEventData.data.resize`；begin 仅 `col/oldWidth`，changed/ended 带 `newWidth`，ended 带 `canceled`。不要与 CR-001/002 的顶层字段方案混用。
- **`End(commit=0)` 与 `Cancel`**：两者都恢复 oldWidth 并发 `ended{canceled=1}` 还是只有一次事件？建议明确：成功 Begin 后，End/Cancel 必须恰好一次 `ended`；失败调用不发事件。
- **`Update` 无 session**：返回 -1.0f 可以，但请确保不会把 -1 传给 `setColumnWidth`；设计器侧需忽略该返回值。
- **外部宽度变更**：session 中 `setColumnWidth`/`setColumns`/列增删/隐藏/禁用/销毁需取消 session 或声明“外部变更立即取消”；建议取消，避免 oldWidth 失真。
- **命中坐标**：`HitTestColumnDivider`/`Begin/Update` 的 `localX/localY` 需明确是 ListView 局部逻辑坐标（含滚动偏移前的坐标口径），设计器侧如何换算写入文档；避免 DPI/缩放/水平滚动下偏差。
- **changed 去重**：同坐标重复 `Update` 不发 `changed`，只在宽度变化时发。
- **旧 DLL 回退**：Binding 缺入口返回 -1/false 已写；补充“不会改变列宽”的测试。
- **测试**：增加 session 与运行时 `m_dragCol` 并发、隐藏/销毁、列增删、外部 `setColumnWidth`、`changed` 去重、事件恰好一次 ended。

## 3. 统一生命周期/焦点建议

建议在 CR-001 的共享机制中先定义一张表，CR-002/003 复用：

| 触发 | 行为 | 是否发事件 |
|---|---|---|
| Enter / 焦点转移（可写） | 写回 + 销毁 + 恢复焦点 | `edited` |
| Enter / 焦点转移（只读） | 不写回 + 销毁 + 恢复焦点 | `cancel`（readOnly=1） |
| Esc | 不写回 + 销毁 + 恢复焦点 | `cancel` |
| 滚动/列宽/行增删移/排序/刷新/隐藏/禁用 | 不写回 + 销毁 | `cancel` |
| 控件销毁 | 只清理，不回调 | 不发（避免失效句柄） |
| 列 resize session 期间编辑 | 取消编辑 | `cancel` |
| 编辑期间列 resize | 取消 resize 或拒绝 | 按 CR-003 定稿 |

焦点规则：

- 键盘 Enter/Esc 结束编辑后，焦点回到 ListView/TreeView（或进入编辑前焦点）；
- 鼠标点击其他控件导致的失焦提交，不抢回焦点；
- 销毁控件不得留下 `FocusManager` 悬垂指针。

## 4. 测试补充（在三份设计现有测试计划上）

1. **ABI 安全**：`UIEventData` 尺寸/union 偏移静态断言；旧 DLL 事件回调读扩展字段不越界（Binding 探针模拟）。
2. **覆盖层**：首行/末行/部分可见/横向滚动/滚动条附近；不越过表头、滚动条、控件边界；点击覆盖层不触发行选择。
3. **焦点**：Enter/Esc 后焦点恢复；点击其他控件；销毁编辑中控件不崩溃。
4. **Tab**：按定稿语义验证（提交/不切换或提交且切换）。
5. **只读**：可进入、可选择/复制、Enter/失焦 cancel、无 edited、readOnly 标志正确；只读属性 round-trip。
6. **事件前后值**：begin/cancel 仅 old、edited old+new；只读属性与 Accessor 一致；字符串在回调内有效。
7. **CR-003 并发**：API session + 运行时 `m_dragCol`、隐藏/销毁、列增删、外部 `setColumnWidth`、`changed` 去重、`ended` 恰好一次。
8. **旧 DLL 回退**：新 Binding 缺入口时 hit/Begin/Update/End 返回值与宽度不变。
