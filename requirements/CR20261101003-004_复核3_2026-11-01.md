### 阻塞点

**`SetColumnResizeCursor(active=0)` 在隐藏/禁用时返回 0 且不改变光标，会导致 EW 光标卡死。**

- §7.2.3 规定 `active=0 → Cursor::getDefault()`；§7.2.3 又写隐藏/禁用/未 create/销毁中 `active` 非 0/1 才失败，但同段第 186 行进一步写“`active=0` 在隐藏/禁用时也直接返回 0”。
- 若控件已显示 EW 后被隐藏，设计器/宿主调用 `SetColumnResizeCursor(0)` 恢复，会被拒绝，光标停留在左右双箭头。
- 建议：**`active=0` 始终允许并恢复默认光标**；仅 `active=1` 在隐藏/禁用/未 create/销毁中失败。`SetColumnResizeCursor(0)` 对无有效句柄的失败可以返回 0，但不能阻止全局光标恢复。
- 补测试：显示 EW → 隐藏/禁用 → `SetCursor(0)` 恢复默认；`SetCursor(1)` 在隐藏/禁用返回 0 且不改变光标。

### 阻塞点

#### B1. `ControlImpl::handleEvent` 只返回 bool，ListView 无法知道是哪个子控件消费

CR004 §4.5 计划：

> MouseDown 被子控件消费时记录 `m_cellControlCaptured`（控件指针/行/列）。

但实际分发是：

1. `ListView::handleEvent` 调 `ControlImpl::handleEvent(event)`；
2. `ControlImpl` 逆序找子控件，命中且 `handleEvent()` 返回 true 就返回 **bool**；
3. ListView 只得到“有人消费”，**拿不到是哪个 cell control 消费**，因此无法记录 captured 指针/行/列。

需要新增可控的子控件派发能力，例如：

- `ControlImpl::dispatchToChild(Event, Control** consumedChild)`（或等价的受保护 helper）；
- 或 ListView 自己做 cell control 命中 + 直接派发，同时避免与 `ControlImpl::handleEvent` 重复派发；
- 或者 Viewport/ControlImpl 提供 hover/capture 信息。

仅靠现有 bool 返回值无法实现 CR004 的“captured 控件 MouseUp 即使移出仍派发”。

#### B2. captured 与“子控件统一派发”顺序矛盾

§4.5 第 1 条要求 ListView **开头先调用 `ControlImpl::handleEvent`**（所有子控件）；但事件表 MouseUp/MouseMove 又要求：

- MouseUp：① captured 控件优先；
- MouseMove：① captured 控件优先。

如果先调用 `ControlImpl::handleEvent`，指针下的**其它子控件**可能先消费 MouseUp/Move；captured 按钮收不到抬起，可能保持 pressed 或丢失 release。需要定稿：

- MouseDown：子控件统一派发，记录 consumed child；
- MouseUp/MouseMove：若 captured：
  1. 先派发 captured；
  2. 若未消费，再派发其它子控件（或按需跳过 captured，防双重派发）；
  3. 最后才进 ListView 自身逻辑；
- MouseWheel：子控件统一派发；
- 明确 captured 控件被隐藏/移除/滚出视口时的清理和 pressed 复位。

#### B3. 测试应覆盖 captured 行为

增加：

- 按下 cell Button → 指针移出 → MouseUp：按钮 release/pressed 复位，行不误选；
- MouseDown 子控件消费 → 指针移到另一 cell control → MouseUp：只有 captured 收到；
- captured 控件滚出内容区/隐藏/删除：captured 清空，不崩溃；
- FILL Panel 空白区 MouseDown 未消费 → 行选择；按钮消费 → 不选行；
- `MouseWheel` 覆盖 cell control 时是否消费。
