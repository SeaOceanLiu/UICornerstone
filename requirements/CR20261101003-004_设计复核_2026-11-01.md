## 1. CR003：通过项与必须修正项

### 已认可
- 8px 命中区、EW 左右双箭头光标由引擎统一管理；
- 运行时与 `ListViewHitTestColumnDivider` 共用命中区；
- 最后一列在右边界/滚动条附近保留可拖区；
- 事件/API 签名不变，`changed` 去重、`ended` 恰好一次；
- 隐藏/禁用/未 create/销毁的失败语义。

### 必须修正

1. **文档内 4px/8px 矛盾**
   - §4.1 的 `HitTestColumnDivider` 注释、§5 Q-1、§6 测试 1 仍写 4px；§7.2.1 写 8px。
   - 实施者可能按 4px 实现。请统一全部为 8px（含测试边界）。

2. **最后一列“完全不可见”条件缺失**
   - §7.2.2 的 `hitX = min(columnX(last)+width, contentRight-1)` 在最后一列已完全滚出左侧时仍可能命中（right<=0 或 left>=contentRight）。
   - 需要显式要求最后一列与内容区有交集（例如 `lastLeft < contentRight && lastRight > 0`）才参与命中；否则返回 -1。
   - 同时明确 `current horizontal scroll` 下 `contentRight`、`columnX` 的口径，避免设计器坐标换算偏差。

3. **光标行为自相矛盾**
   - §7.2.3 说 `HitTestColumnDivider` 未命中时“恢复默认”；§7.3 又说非 multi/隐藏/禁用/未 create 时返回 -1、**不改变光标**。
   - 请明确 `HitTest` 是否允许有副作用（推荐：**查询不改变光标**；由设计器在拿到命中结果后调用新的显式光标设置 API，或 `HitTest` 只在设计器明确请求时设置光标）。否则纯查询 API 会意外覆盖其他控件的光标。
   - 若保留“HitTest 命中即设置 EW”，请写明：非命中/失败/隐藏/禁用/销毁是否恢复默认，以及离开 ListView/窗口失焦时的恢复责任。

4. **光标生命周期**
   - 需覆盖 MouseLeave、窗口失焦、隐藏/禁用/销毁、拖拽结束/取消；全局 Cursor 是进程级，多个 ListView/预览窗口同时存在时如何避免互相覆盖，请写明。
   - 光标创建失败时默认光标回退已写，OK。

5. **测试计划**
   - 自动化测试仍写 ±4px；更新为 ±8px，并补：
     - 最后一列左右完全不可见时不命中；
     - 最后一列部分可见时可命中；
     - `HitTest` 非命中/失败时光标状态；
     - 窗口失焦/隐藏/禁用后的光标恢复；
   - 光标视觉项人工/截图验收可接受，但需记录截图路径。

## 2. CR004：通过项与必须修正项

### 已认可
- 通用 per-cell control，而非 action-column 专用；
- 引擎接管所有权，宿主不得 Destroy；
- FILL 2px 横 / 1px 纵，LEADING 复用现有图标槽；
- 仅完整可见显示，部分可见隐藏；
- 行排序/移动随 `ListRow`；行/列删除与 `setColumns` 缩列清理；
- 单控件 + Panel 组合；本期不新增 JSON。

### 必须修正/补充

1. **所有权与 Binding 生命周期**
   - 明确 `SetCellControl` 后调用方 `Control&` 代理是否仍可用、是否应视为借用；`Clear`/替换/删除后宿主代理的 `IsValid` 语义。
   - `GetCellControl` 返回的 handle 是“只读借用”还是可 Destroy；当前文档未写清。
   - `ClearCellControl` 时“若宿主仍持有共享引用则只摘树”会留下脱离树的控件；需说明宿主后续必须丢弃代理，且不得再 Set/使用。
   - 控件已有 parent/context/已经 attach 到其他容器时，Set 应失败还是先 detach；请定稿。
   - 控件替换/删除时若其持有焦点，需主动清焦点，避免 FocusManager 悬垂。

2. **事件派发顺序需成表**
   - 现在只有原则“子控件先、消费则停”，不足以实现。请给出 MouseDown/MouseUp/MouseWheel/MouseMove/双击/拖拽的精确顺序：
     - 子控件（逆 z）→ 是否消费；
     - 未消费时 ListView 是否选行/发 `item-click`/进入 P0-111 编辑；
     - FILL 控件空白区 vs 按钮区；
     - 表头/分隔线/滚动条优先级；
     - 单元格 FILL 控件是否作为“编辑屏蔽区”（尤其双击）；
     - 行拖动/排序在 FILL 控件空白区是否允许。
   - 需确认引擎 Viewport 是否会把鼠标事件先派给子控件；若会，ListView 的“先派给 cell control”应如何与 Viewport 分发配合，避免双重派发。

3. **仅完整可见的边界**
   - 明确“完整可见”是否包含：
     - 纵向完整在内容区；
     - 横向完整在列宽内；
     - 不受垂直/水平滚动条覆盖；
     - 部分可见时隐藏并清焦点，恢复可见时不自动抢焦点。
   - FILL/LEADING 是否都采用“仅完整可见”；若改变 LEADING 现有行为，需标注兼容性影响。

4. **FILL 控件与文本/编辑**
   - FILL 控件会覆盖单元格文本；事件面板操作列的空 Panel 需要透明；请确认透明 Panel 不会拦截空白区点击（或明确拦截）。
   - 同一格 FILL 控件存在时，双击编辑是否完全禁用；控件内部空白双击的行为。
   - 控件隐藏（部分可见）时，如果正在被编辑/聚焦，如何结束；与 P0-111 的取消规则一致。

5. **测试补充**
   - Binding 代理在 Set/Clear/替换/删除后的 `IsValid`；
   - 控件已属于其他父容器时 Set 的失败语义；
   - 焦点在 FILL 控件时行删除/隐藏/滚动出视口；
   - 事件派发顺序的逐项测试（按钮、空白、双击、滚轮、拖拽）；
   - `setColumns` 缩列清理无悬垂/泄漏。

6. **FILL padding**
   - 2/1px 可接受；建议明确这是内容区内缩，不改变单元格文本位置；
   - 事件面板 32px 行高下按钮可用性需实测。
