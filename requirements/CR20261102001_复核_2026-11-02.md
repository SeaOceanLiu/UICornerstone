## 2. 实施前必补

### R1. `ApplyTheme` 的 baseline 必须随主题更新

- 当前 §4.5 写“**首次**应用 CSS 规则前保存 baseline（旧类型主题/控件默认）”。
- 但 `ApplyTheme` 可在运行时替换旧 `fonts/colors`（甚至从旧主题切到新主题）；若 baseline 只在首次保存，**新旧主题的字体/颜色不会进入非显式通道**，旧 baseline 可能残留。
- 要求：`ApplyTheme` 成功替换主题后，按**新主题的旧类型主题 + 控件默认**重建每个控件的 baseline，再应用 CSS 规则；`SetThemeVariant` 按 base+variant 重建；`classes` 变更只恢复当前 baseline。
- 补充测试：旧主题 A → ApplyTheme 旧主题 B / CSS 主题 → 非显式通道使用新主题值；显式通道保持不变。

### R2. padding 的诊断与范围

- 当前范围通过；请在手册/`GetLastError` 明确：非 Label/Button/CheckBox 的 `padding` 声明被诊断忽略，不影响其它声明。
- 若后续要求 Panel/List/Tree 通用内边距，另立 CR（不阻塞本批）。

### R3. `theme-eligible` 的边界

- 补充：内部辅助控件设为 false 时，其**后代/内部子控件**也不参与匹配与继承；用户自行放置的 leadingControl/cellControl 默认 true。
- `theme-eligible` 暴露为通用 Bool 属性时，需说明用户可显式置回 true 的后果。

## 3. 非阻塞建议

- 旧主题/旧布局零回归作为发布门禁。
