## 1. 分项评审

### §2 现状核实 ✓

**49 处 m_dialog 引用的逐点 guard 审计**是本设计最有价值的部分——结论"唯一未守卫：:198 handleEvent KeyDown 路径"给出了精确修正点；setters 的既有 guard（`m_dialog && visible` / `if (m_dialog)`）语义在惰性化下的正确性（构建前写成员、build 时读取）逐条确认 ✓。

### §3.1/3.2 方案 a（整体惰性 + ensurePopupBuilt）✓

- `m_dialog == nullptr` 即未构建标志——零新增状态；`ensurePopupBuilt()` 收敛全部构建逻辑（原 create 的 Dialog 段 + recreatePopupContent），改动集中 ✓。
- **b 不做**（预设网格二次延迟）判断正确：80 格为无字体 Panel，非成本大头——避免状态复杂化。
- **首打开 ~3.5s 与绕行方案的账目对比**（净收益确认）：占位绕行 = 每槽首次点击付 3.5s（15 槽各一次）；惰性化 = 关闭态秒建（15×<35ms）+ 每槽**首次打开弹窗**付 3.5s——**总账等价**，但删除三件套复刻/替换逻辑（负资产清零）+ 关闭态秒建（选中不再卡 500ms 级）——净收益成立。

### §3.3 null-safety ✓

`:198` 修正为 `isPopupVisible()`（未构建 = 不可见 = 关闭，语义自洽）✓；syncUIFromColor/setRect/析构的既有 guard 核对完整。

### §3.4 backlog ✓

c（字体/控件创建共享缓存）与 P1-7 字体预热合并——正确归类（全局问题）；C ABI OpenPopup 不做——设计器确认当前不需要。

### §5 验收 / §6 风险 ✓

量化阈值（15 实例 <500ms）+ 行为断言（弹窗子树未建/首次打开齐全/二次零重建/构建前 setter 生效）+ 键盘路径不崩 + 全量回归——覆盖完整。**验收 3（构建前 setter 生效）尤其关键**——设计器"create → SetString(hex 初始色) → 用户交互"路径依赖它。
