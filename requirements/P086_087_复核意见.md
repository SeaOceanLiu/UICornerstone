## 1. P0-86 补充（Binding 空函数分支）

1. **空函数分支须在 slot 创建/push 之前返回**：现 `Control::SetCallback` 先 `make_shared<EventCallback>` + `callbackUserData[handle].push_back(slot)` 再调 fnSetCallback。若实现时只把「fnSetCallback 参数换 nullptr」，槽仍会堆积（每次解绑多一条无主槽）。建议：`if (!callback) { fnSetCallback(inst, handle, event, nullptr, nullptr); return; }` 置于函数首部（IsValid 检查之后）。
2. **设计器过渡随批**：同步后我们把 `removeEventBinding` 的 `[](const Event&){}`（no-op 防崩过渡）改回 `SetCallback(bind, nullptr)`，并跑原崩溃复现回归（打开 `First Project.csd` → 点击按钮 = 旧 VC 运行库异常场景，改后应零崩溃）。
3. Q-3 补充承诺：引擎探针之外，设计器提供端到端验证——auto=2 全量（82 所属断言）+ 手动点击复现，随同步批次回报。

## 2. P0-87 补充（菜单项 id 注册）

1. **注册条件化**：仅对**携带 `id` 的项**注册（设计已隐含）；空 id/无 id 项跳过，不引入空键。
2. **同 id 覆盖语义**：与现有控件一致（后注册覆盖）即可，无需额外查重；建议在 tablet 文档一句话注明「菜单项 id 与控件 id 同表，重名互相覆盖」。
3. **重载残留**：`LoadLayout` 若不清 `controlsById` 就合并新表，重复加载会残留旧菜单项句柄（生命周期由 bench/popupPool 持有，风险面小）。设计器预览路径为「重建实例」，实际不触发；建议实现时顺带确认该合并点的清理策略（**非阻塞**，注明行为即可）。
4. **te 测补充**：除设计中的探针外，建议加「无 id 项不注册（FindControl 返回空）」1 例；子菜单项探针设计已含 ✓。
5. 设计器侧联测计划（同步后）：auto=1 探针 `miUndo valid=1`；空栈时撤销/重做灰显且点击忽略；放置→撤销→重做全过程的灰显状态翻转；`refreshMenuStates` 首帧即写（初始可用态缓存 true→false 变化触发 ✓ 无需修改）。
