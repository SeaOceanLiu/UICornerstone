### ✗ 必改：细化 2 判据 `kind == UI_DRAG_KIND_NONE` 不成立（防护会完全失效）

`captureDragPayload`（`UICornerstoneAPI.cpp:1009`）**首行即置 `s.kind = UI_DRAG_KIND_CONTROL`**——`UI_DRAG_KIND_NONE`(=0) 仅在捕获前存在，**捕获后永不为 NONE** ✗。按现文档实现，"tab 页体 / 树空白 / 列表空白误起拖"防护完全失效 ✗。

**修正**：判据改为 `s->kind == UI_DRAG_KIND_CONTROL`（= 未命中任何可重排项、且无 `drag-data`/`drag-userdata` 覆盖的缺省态；CONTROL 即"无具体载荷"语义）：

```cpp
captureDragPayload(*s, src, evt.mouseButton.x, evt.mouseButton.y);
if (!srcImpl->isDraggable() && s->kind == UI_DRAG_KIND_CONTROL) {
    dragReset(*s);
    return false;   // 不进入 Pending，点击语义保留
}
return false;
```

语义核对：item 命中（TREE_NODE / LIST_ROW / TAB_PAGE）→ 起拖 ✓；HOST 覆盖（drag-data/drag-userdata）→ 起拖 ✓；CONTROL 缺省 → 取消 ✓。空标题 tab（id 为空）不受影响（按 kind 判定，不依赖 id ✓）。

### ⚠ 可选建议（UX 质量，可并入本批）

1. **自目标 tab 落点索引**：`computeDropHint` 的 tab 分支仅在光标位于某 `tabRect` 内时定 `ins`，否则 `ins = tabs.size()`（自目标拖到页体上方松手 → 落尾 ✗）。建议自目标场景按 `lx` 单轴计算插入位（clamp 到 `[0, n]`），与设计器宿主侧 `tabItemIndexAt` 口径一致 ✓（外部 droppable 场景同受益 ✓）。
2. **自目标 drop 事件语义明示**：自目标路径会同时发 `drop`（target=源自身）+ `tab-reordered`/`reordered`——与 droppable=自身既有行为一致（无回归 ✓），建议在 `P093_094_DragDrop_Design.md` 实施备注中明示（宿主勿把内置换序误当外部投放）✓。
3. **测试矩阵**："全量回归仅 4 项预存失败"——请列出这 4 项（确认与本项改动面 `UICornerstoneAPI.cpp` 无交集）✓。
