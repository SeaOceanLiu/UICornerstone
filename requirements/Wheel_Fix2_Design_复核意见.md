## 1. 分项评审

### §3.1 Panel 空转消费修复 ✓（根因定位源码级成立）

- **无条件 `return true` 缺陷确认**（Panel::handleEvent 现状：无订阅者也消费），N1-N4 对照测试扎实（单层/深嵌套/经 TabControl/遮挡全通）。
- **修复语义**（"wheel 由最近的有订阅者 Panel 消费"，hasCallback 门控 + 无订阅透传）——与"事件冒泡直至被订阅者消费"的通用模型一致 ✓，O(1) 查询成本无感 ✓。
- **与设计器观察的可调和性**：设计器测试时若鼠标在固定区（非动态区 288px 内），`propDynamic` 不命中 → `tabProperty`（无订阅）空转吞 → 回调零触发——与实测吻合 ✓。

### §3.2 TextArea 可滚性门控 ✓

- `getMaxScrollY() <= 0` 透传语义正确；"滚动到底后不回滚透传"的取舍**确认接受**（与主流编辑器一致，链式滚动无需求）。
- ListView/TreeView 同型排查随批 ✓。

### §3.3 NUD 焦点门控 ✓

- 仅聚焦消费、未聚焦透传——标准交互 ✓；CheckBox 参照形态正确。

### §3.5 坐标域勘误 ✓

- HandleHitTest 注释修正（窗口坐标原样）与 GetRect/getDrawRect 域对照小节——正合设计器两度踩坑所需 ✓。

## 3. 放行条件与质询

### 3.1 N6 对照测试（放行条件）

设计器实测的**完整场景**需最小复现验证：

> **内层 Panel 挂订阅（有回调）、外层 Panel 无订阅、鼠标在内层面板内** → 内层回调**应触发**。

- 按 §3.1 修复后的语义，该场景**修复前**也应成立（内层 fire 有订阅）——但设计器实测（ComboBox 动态行，鼠标在动态区内）回调零触发，与"内层订阅应触发"存在张力。
- **要求**：引擎在 `test_wheel_nested_cabi` 补 **N6**（三层嵌套：外层无订阅 / 内层有订阅 / 鼠标内层内），给出**修复前后**两组数据：
  - 若修复前即通过 → 设计器零触发另有其因（可能为鼠标坐标与内层 getDrawRect 的交集问题），请引擎进一步定位后设计器联测；
  - 若修复前失败、修复后通过 → 空转定位完整，设计器直接联测。
- **设计器侧配合验证**：联测时在回调内打印鼠标坐标与 propDynamic 的 `getDrawRect`（经测试探针）对照交集。

### 3.2 补充观察（不阻塞）

设计器测试日志中鼠标在动态区内滚动时 `[MW]` 亦零输出——请 N6 时顺带覆盖"内层订阅 + 鼠标确在内层坐标内"的断言（可注入精确坐标），排除"命中但坐标域不匹配"的静默路径。

## 4. 设计器侧配合调整（随本批实施）

1. **订阅层级上移**：`mouse-wheel` 订阅从 `propDynamic`（动态区容器）**上移至 `tabProperty`**（属性页容器，覆盖整个面板）——与"最近订阅者消费"语义一致，且符合用户预期（在属性面板任意位置滚轮均滚动动态区）：
   - 修复后链路：鼠标在面板任意处 → 内层无订阅 Panel 透传（或行控件门控透传）→ `tabProperty` 消费 ✓；
2. 回收项：无（Win32 钩子已在本批前回收）。

## 5. 放行

**结论：放行实施**（5 项确认 + §4 配合）。联测清单：

- 鼠标在动态区内/外滚动 → 属性行均滚动（订阅上移后全面板覆盖）；
- 滚轮在 TextArea（无可滚）/NUD（未聚焦）行上 → 透传滚动面板；可滚/聚焦时各自消费；
- 滚轮在滚动条上 → 步进；画布上 → 不误滚；
- N6 数据回传后复核。
